Developing L Modules

Adding Models for Aquatic Mosquito Ecology

This vignette describes how to add a model of aquatic mosquito ecology to ramp.library. Read the ramp.xds L interface vignette first for an overview of how L modules connect to egg laying and emergence. Before adding a module, check whether the model is already available in the SimBA library.

An L module describes aquatic mosquito states in larval habitats. Its methods operate on the habitat dimension, nHabitats, and use s as the vector-species index. The habitat-to-patch membership vector is provided when the module is set up.

Creating a module template

The code chunks below can be extracted to create a starting R file. From the directory containing this vignette, run:

knitr::purl(
  "L-How_To_Add_Model.Rmd",
  output = "Lmodule-newLname.R",
  documentation = 0,
  quiet = TRUE
)

The resulting file contains code examples that must be adapted before the module is used. Replace newLname with a short, model-specific name. When rendered, the chunks define the example functions but do not call them.

General conventions

  • Implement model methods as S3 methods named with the module class, such as dLdt.newLname.
  • Use s to access the module at xds_obj$L_obj[[s]].
  • Store state indices in xds_obj$L_obj[[s]]$ix, with one index per habitat for each habitat-level state.
  • Keep state variables, derivatives, and discrete updates in the same order.
  • Document model equations, states, parameters, inputs, outputs, and references with roxygen.
  • Add tests for the module’s equations, dimensions, and setup behavior.

Documentation policy

Follow the shared function order in module files and guide implementation sections. Move functions with their documentation, keep file-level review/TODO notes at the top, and preserve definitions and behavior when reordering.

Follow the shared documentation conventions and the L setup wording. These vignettes are the public style reference for both packages.

  • Use the approved family titles with a backticked module name and the L tag, including “Compute the derivatives for module (L)”, “Mosquito bionomics for module (L)”, and “Apply effect sizes for module (L)”.
  • Show the equations actually implemented, matching the returned state order. Describe derivative and updating equations separately, including any accessory variables and branches.
  • Keep storage, class assignments, and dispatch mechanics in @note. Explain dispatch on the generic, not repeatedly on each method.
  • List setup actions in implementation order: construction using nHabitats and options, initial values, habitat search weights, and return of the updated xds model object.
  • Describe the habitat step as “Initialize habitat search weights using [ramp.xds::setup_habitat_search_weights.setup].” End complete bullets with periods and qualify links to shared helpers with ramp.xds::.
  • Describe skill sets as capabilities and compatibilities returned on demand by get_skillset_L; do not store them on the module object. Include dts = FALSE if no discrete-time update method is defined; only advertise supported and tested solver pathways.
  • State when a check method returns the model unchanged without checks.

Both dynamics methods below are placeholders. Keep the methods required by the new module, replace the equations and their documentation together, and update the skill set accordingly.

Module dynamics

Implement dLdt.newLname for a continuous-time model, or Update_Lt.newLname for a discrete-time model. Both receive time t, the dependent-variable vector y, the xds model object, and the species index s. A continuous-time method returns derivatives; a discrete-time method returns updated states. They are alternative solver interfaces, not interchangeable equations.

The habitat-level egg input is available as xds_obj$terms$eta[[s]]. Extract the module states with get_L_vars and use the indices and parameter values stored on the module object.

State-variable extraction

#' @title Get the state variables for `newLname` (**L**)
#' @description Extract the state variables for the `newLname` module
#' from `y` and return them by name in a list for use during model solving.
#' @note Variable indices are stored at `xds_obj$L_obj[[s]]$ix`.
#' @inheritParams ramp.xds::get_L_vars
#' @return a named [list] of state variables and module-specific derived quantities
#' @export
get_L_vars.newLname <- function(y, xds_obj, s) {
  with(xds_obj$L_obj[[s]]$ix, {
    L <- y[L_ix]
    return(list(L = L))
  })
}

If the module has more than one state variable, create an index range for each one and include each named state in the returned list.

Bionomics and effect sizes

LBionomics.newLname updates baseline parameter values at time t and resets effect sizes. LEffectSizes.newLname applies the configured effect sizes to those baseline values. Implement these methods for parameters that use time-varying forcing or vector-control effects; use the existing bionomics forcing functions where they match the parameter.

For each parameter x configured as a port, store its baseline as x_t, its effect size as es_x, and its effective value as x. Parameters without ports are stored directly as x and are not modified by effect sizes. The example assumes p1 has a configured port and that F_p1(t, xds_obj, s) evaluates it; p2 is a direct parameter without a port.

Inherit the module NULL anchor’s Parameters section and link the paired methods reciprocally and to the module. Describe baseline evaluation and effect-size application separately, keeping stored fields and assignments in @note. For modules without ports, such as stages, describe the actual no-op behavior rather than claiming that parameters or effects are updated. Keep dispatch documentation on the shared generics.

#' @title Compute the baseline p1 parameter
#' @inheritParams ramp.xds::F_psi
#' @return a numeric vector of length `nHabitats`
#' @export
F_p1 <- function(t, xds_obj, s) {
  UseMethod("F_p1", xds_obj$L_obj[[s]]$p1_obj)
}

#' @rdname F_p1
#' @export
F_p1.static <- function(t, xds_obj, s) {
  xds_obj$L_obj[[s]]$p1_obj$p1
}

#' @title Mosquito bionomics for `newLname` (**L**)
#' @description Update baseline parameters and reset effect sizes.
#' @inheritSection newLname Parameters
#' @note Store the evaluated baseline as `p1_t` and reset `es_p1` to 1
#' per habitat at `xds_obj$L_obj[[s]]`. Leave the direct parameter `p2` unchanged.
#' @inheritParams ramp.xds::LBionomics
#' @seealso [newLname], [LEffectSizes.newLname]
#' @return an **`xds`** model object
#' @export
LBionomics.newLname <- function(t, y, xds_obj, s) {
  with(xds_obj$L_obj[[s]], {
    # Replace these assignments with the appropriate forcing functions.
    xds_obj$L_obj[[s]]$p1_t <- F_p1(t, xds_obj, s)
    xds_obj$L_obj[[s]]$p2 <- p2
    xds_obj$L_obj[[s]]$es_p1 <- rep(1, xds_obj$nHabitats)
    return(xds_obj)
  })
}

#' @title Apply effect sizes for `newLname` (**L**)
#' @description Apply vector-control effect sizes to baseline parameters.
#' @inheritSection newLname Parameters
#' @note Set `p1 = p1_t * es_p1` at `xds_obj$L_obj[[s]]`.
#' Do not evaluate ports, reset effect sizes, or change the direct parameter `p2`.
#' @inheritParams ramp.xds::LEffectSizes
#' @seealso [newLname], [LBionomics.newLname]
#' @return an **`xds`** model object
#' @export
LEffectSizes.newLname <- function(t, y, xds_obj, s) {
  with(xds_obj$L_obj[[s]], {
    xds_obj$L_obj[[s]]$p1 <- p1_t * es_p1
    return(xds_obj)
  })
}

Module object and setup

Use the constructor title “Make a module object for module (L)”. Describe parameter initialization and options overrides. The constructor, parameter getter, and parameter changer each link to the other two in @seealso; describe any differences in their parameter coverage.

make_L_obj_newLname creates the module object and initializes its parameters. setup_L_obj.newLname attaches the object at xds_obj$L_obj[[s]], sets up initial values, and configures habitat search weights using the supplied membership vector.

#' @title Make a module object for `newLname` (**L**)
#' @description Create a `newLname` module object and initialize its parameters.
#' Inspect parameters with [get_L_pars.newLname] and change supported values
#' with [change_L_pars.newLname]. Values in `options` override parameter arguments.
#' @seealso [get_L_pars.newLname], [change_L_pars.newLname]
#' @param nHabitats the number of habitats in the model
#' @param options a named list of parameter values
#' @return an L module object
#' @export
make_L_obj_newLname <- function(nHabitats, options = list(), p1 = 1, p2 = 1) {
  with(options, {
    L_obj <- list(
      p1 = ramp.xds::checkIt(p1, nHabitats),
      p2 = ramp.xds::checkIt(p2, nHabitats),
      p1_t = ramp.xds::checkIt(p1, nHabitats),
      es_p1 = rep(1, nHabitats),
      p1_obj = structure(list(p1 = ramp.xds::checkIt(p1, nHabitats)),
                         class = "static"),
      nHabitats = nHabitats
    )
    class(L_obj) <- "newLname"
    return(L_obj)
  })
}

#' @title Set up the module object for `newLname` (**L**)
#' @description Set up a `newLname` module object for the **L** component
#' and the \eqn{s^{th}} vector species.
#' + Create the module object with [make_L_obj_newLname], passing `nHabitats` and `options`.
#' + Set initial values using [ramp.xds::setup_L_inits], passing `options` to override defaults.
#' + Initialize habitat search weights using [ramp.xds::setup_habitat_search_weights.setup].
#' + Return the updated **`xds`** model object.
#' @note The module object is stored at `xds_obj$L_obj[[s]]`.
#' Its classes are `newLname` and `newLname_` followed by `xds_obj$xds`.
#' @inheritParams ramp.xds::setup_L_obj
#' @return an **`xds`** model object
#' @export
setup_L_obj.newLname <- function(Lname, membership, xds_obj,
                                 options = list(), s = 1) {
  L_obj <- make_L_obj_newLname(xds_obj$nHabitats, options)
  class(L_obj) <- c("newLname", paste0("newLname_", xds_obj$xds))
  xds_obj$L_obj[[s]] <- L_obj
  xds_obj <- ramp.xds::setup_L_inits(xds_obj, options = options, s = s)
  xds_obj <- ramp.xds::setup_habitat_search_weights(
    "setup", xds_obj, list(membership = membership), s = s
  )
  return(xds_obj)
}

Parameters

The shared ramp.xds::change_psi, ramp.xds::change_phi, ramp.xds::change_xi, and ramp.xds::change_theta helpers are intended for individual static basicL parameters, not arbitrary module-specific fields. They accept numeric scalars or values of length nHabitats, expand scalars across habitats, and error on invalid types or lengths. For parameter x, they update xds_obj$L_obj[[s]]$x and, when x_obj is present, also x_t and x_obj$x. They leave the port class and es_x unchanged, do not evaluate ports or apply effect sizes, and return the updated model object. They do not dispatch on module or port class and should not be used to reconfigure dynamic ports.

Their titles retain “Change the parameter (L)”, using the full parameter name. Descriptions identify the static basicL scope, inherit its Parameters section, and link to the matching getter. Keep storage and port-field updates in @note. New modules should implement their own change_L_pars method for their supported parameters.

Implement get_L_pars.newLname to return the module parameters as a named list, and change_L_pars.newLname to update the parameters named in options while leaving other parameters unchanged. Check supplied values against xds_obj$nHabitats; parameter vectors should match the habitat dimension.

#' @title Get parameters for `newLname` (**L**)
#' @description Return the parameters for the `newLname` module as a named list.
#' @seealso [make_L_obj_newLname], [change_L_pars.newLname]
#' @inheritParams ramp.xds::get_L_pars
#' @return a named [list] of parameter values
#' @export
get_L_pars.newLname <- function(xds_obj, s = 1) {
  with(xds_obj$L_obj[[s]], {
    return(list(p1 = p1, p2 = p2))
  })
}

#' @title Change parameters for `newLname` (**L**)
#' @description Change parameter values named in `options` for the `newLname`
#' module, leaving other values unchanged.
#' Update the `p1` port and the direct parameter `p2`.
#' The effective `p1` value is set by [LEffectSizes.newLname].
#' Call [ramp.xds::LBionomics] at time zero after the updates,
#' without calling [ramp.xds::LEffectSizes].
#' @seealso [make_L_obj_newLname], [get_L_pars.newLname]
#' @inheritParams ramp.xds::change_L_pars
#' @return an **`xds`** model object
#' @export
change_L_pars.newLname <- function(xds_obj, options = list(), s = 1) {
  nHabitats <- xds_obj$nHabitats
  if ("p1" %in% names(options)) {
    xds_obj$L_obj[[s]]$p1_obj$p1 <- ramp.xds::checkIt(options$p1, nHabitats)
  }
  if ("p2" %in% names(options)) {
    xds_obj$L_obj[[s]]$p2 <- ramp.xds::checkIt(options$p2, nHabitats)
  }
  y <- ramp.xds::get_inits(xds_obj, flatten = TRUE)
  xds_obj <- ramp.xds::LBionomics(0, y, xds_obj, s)
  return(xds_obj)
}

State indices

Retrieve stored indices with the shared ramp.xds::get_L_ix(xds_obj, s = 1); do not implement a module-specific getter. setup_L_ix.newLname assigns a contiguous range of indices to each state. Allocate one index per habitat for each habitat-level state, and update max_ix after each range. get_L_vars.newLname extracts named states from the dependent-variable vector y.

Use the title and description below, documenting actual block order and lengths. Put index storage and the updated maximum in @note, and return the model object rather than the index list. Record implementation exceptions separately during documentation alignment.

#' @title Set up variable indices for `newLname` (**L**)
#' @description Assign consecutive variable indices for the `newLname` module,
#' starting after `xds_obj$max_ix`, and update the maximum index.
#' Allocate the `L_ix` block with length `nHabitats`.
#' @note Indices are stored at `xds_obj$L_obj[[s]]$ix`.
#' The maximum index is stored at `xds_obj$max_ix`.
#' @inheritParams ramp.xds::setup_L_ix
#' @return an **`xds`** model object
#' @importFrom utils tail
#' @export
setup_L_ix.newLname <- function(xds_obj, s) {
  L_ix <- seq(from = xds_obj$max_ix + 1, length.out = xds_obj$nHabitats)
  xds_obj$max_ix <- utils::tail(L_ix, 1)
  xds_obj$L_obj[[s]]$ix <- list(L_ix = L_ix)
  return(xds_obj)
}

Optional methods

steady_state_L.newLname is optional when a steady-state calculation is available. It receives habitat-level daily egg input eta and returns a named list of steady-state values. Use “Compute steady states for module (L)” for method titles, describe the supported equation system, and name the returned states. The generic dispatches on xds_obj$L_obj[[s]]. To support both differential-equation and discrete-time calculations, follow basicL’s second-stage dispatch on xds_obj$xds; do not assume every module implements both. Return values are not stored on the model object. The shared get_L_orbits, xds_plot_L, and xds_lines_L functions provide access to and visualization of parsed model output; a module-specific plotting method is not required.

The basicL reference model

The basicL module in ramp.xds is an example of a habitat-level model. It tracks larval density \(L\) and implements

\[\frac{dL}{dt} = \eta - \left(\psi e^{-\xi L} + \phi + \theta L\right)L, \qquad \alpha = \psi e^{-\xi L}L.\]

Its states and parameters each have one value per habitat. Consult aquatic-L-basicL.R in the ramp.xds source for a complete implementation of its setup, parameter, dynamics, initial-value, emergence, and output methods.
