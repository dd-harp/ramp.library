Developing MY Modules

Models for Adult Mosquito Ecology and Infection Dynamics

This vignette describes how to add an adult mosquito (MY) model module to ramp.library. Before creating a new module, check whether the model family is already available in the SimBA library. For an overview of the component interfaces, see the ramp.xds MY interface vignette.

An MY module represents adult mosquito ecology and, when applicable, pathogen infection dynamics in mosquitoes. It supplies methods that integrate with ramp.xds, which provides the shared model setup, transmission, egg-laying, and solver interfaces.

Create a module template

This vignette’s R code chunks can be extracted to create a starting R file. Download MY-How_To_Add_Model.Rmd, set your working directory to the folder containing it, then run:

knitr::purl(
  "MY-How_To_Add_Model.Rmd",
  output = "adult-MY-newMYname.R",
  documentation = 0,
  quiet = TRUE
)

Replace newMYname throughout the extracted file with a short, unique class name for the model. Review every placeholder and adapt the methods to the model’s equations and state variables before using the file.

Conventions

  • MY methods dispatch on the class of xds_obj$MY_obj[[s]]; use s as the vector-species index in method signatures and calls.
  • Use get_MY_vars(y, xds_obj, s) to retrieve named state variables, and keep the order of variables consistent across setup_MY_ix, get_MY_vars, initial values, and the dynamics.
  • Document the model’s state variables, parameters, equations, assumptions, and relevant references in roxygen.
  • Add tests for setup, parameter and initial-value changes, dynamics, and any model-specific outputs.

Model object and state variables

make_MY_obj_newMYname creates the module-specific list and assigns its class. setup_MY_obj.newMYname attaches it to the full xds_obj. Include the parameters and any model-specific objects needed by the equations. Parameters that use the shared bionomics or dispersal interfaces should be set up with the corresponding ramp.xds helpers.

#' @title Make the model object for newMYname
#' @param nPatches number of patches
#' @param options named values that override defaults
#' @return a list
#' @export
make_MY_obj_newMYname <- function(nPatches, options = list(), p1 = 1) {
  with(options, {
    MY_obj <- list()
    MY_obj$p1 <- checkIt(p1, nPatches)
    MY_obj$nPatches <- nPatches
    class(MY_obj) <- "newMYname"
    MY_obj
  })
}

#' @title Set up the newMYname MY module
#' @description Implements [ramp.xds::setup_MY_obj] for newMYname.
#' @inheritParams ramp.xds::setup_MY_obj
#' @return an **`xds`** model object
#' @export
setup_MY_obj.newMYname <- function(MYname, xds_obj, options = list(), s = 1) {
  xds_obj$MY_obj[[s]] <- make_MY_obj_newMYname(xds_obj$nPatches, options)
  xds_obj$MY_obj[[s]]$skill_set <- get_skillset_MY(xds_obj, s)
  xds_obj <- setup_MY_inits(xds_obj, options = options, s = s)
  xds_obj
}

State-variable indices

setup_MY_ix.newMYname assigns a contiguous index range to each state variable. The example follows the SI implementation; add or remove index ranges to match the model and store them in the named list at xds_obj$MY_obj[[s]]$ix.

#' @title Set up indices for newMYname
#' @description Implements [ramp.xds::setup_MY_ix] for newMYname.
#' @inheritParams ramp.xds::setup_MY_ix
#' @return an **`xds`** model object
#' @importFrom utils tail
#' @export
setup_MY_ix.newMYname <- function(xds_obj, s) {
  with(xds_obj, {
    M_ix <- seq(from = max_ix + 1, length.out = nPatches)
    max_ix <- tail(M_ix, 1)

    Y_ix <- seq(from = max_ix + 1, length.out = nPatches)
    max_ix <- tail(Y_ix, 1)

    xds_obj$max_ix <- max_ix
    xds_obj$MY_obj[[s]]$ix <- list(M_ix = M_ix, Y_ix = Y_ix)
    xds_obj
  })
}

get_MY_vars.newMYname maps the dependent-variable vector y to the named state variables used in the equations. Include only variables that belong to the module’s state vector; do not add host variables unless they are actual MY states.

#' @title Get newMYname state variables
#' @description Implements [ramp.xds::get_MY_vars] for newMYname.
#' @inheritParams ramp.xds::get_MY_vars
#' @return a named list
#' @export
get_MY_vars.newMYname <- function(y, xds_obj, s) {
  with(xds_obj$MY_obj[[s]]$ix, {
    list(
      M = y[M_ix],
      Y = y[Y_ix]
    )
  })
}

parse_MY_orbits.newMYname extracts the same state variables from the solver output matrix. It can also return derived quantities, such as prevalence or parity, when those quantities are defined for the model.

#' @title Parse newMYname model output
#' @description Implements [ramp.xds::parse_MY_orbits] for newMYname.
#' @inheritParams ramp.xds::parse_MY_orbits
#' @return a named list
#' @export
parse_MY_orbits.newMYname <- function(outputs, xds_obj, s) {
  with(xds_obj$MY_obj[[s]]$ix, {
    M <- outputs[, M_ix]
    Y <- outputs[, Y_ix]
    list(M = M, Y = Y)
  })
}

Initial values

make_MY_inits_newMYname returns a named list containing an initial value for every state variable. setup_MY_inits.newMYname stores those values in the module object, and change_MY_inits.newMYname updates named values after setup.

#' @title Make newMYname initial values
#' @param nPatches number of patches
#' @param options named values that override defaults
#' @param M initial adult mosquito density
#' @param Y initial infected mosquito density
#' @return a named list
#' @export
make_MY_inits_newMYname <- function(nPatches, options = list(), M = 10, Y = 1) {
  with(options, {
    M <- checkIt(M, nPatches)
    Y <- checkIt(Y, nPatches)
    list(M = M, Y = Y)
  })
}

#' @title Set up newMYname initial values
#' @description Implements [ramp.xds::setup_MY_inits] for newMYname.
#' @inheritParams ramp.xds::setup_MY_inits
#' @return an **`xds`** model object
#' @export
setup_MY_inits.newMYname <- function(xds_obj, options = list(), s = 1) {
  xds_obj$MY_obj[[s]]$inits <-
    make_MY_inits_newMYname(xds_obj$nPatches, options)
  xds_obj
}

#' @title Change newMYname initial values
#' @description Implements [ramp.xds::change_MY_inits] for newMYname.
#' @inheritParams ramp.xds::change_MY_inits
#' @return an **`xds`** model object
#' @export
change_MY_inits.newMYname <- function(xds_obj, options = list(), s = 1) {
  xds_obj$MY_obj[[s]]$inits[names(options)] <- options
  xds_obj
}

Parameters and bionomics

Implement get_MY_pars.newMYname and change_MY_pars.newMYname for the parameters users should inspect and change. For bionomic parameters managed through shared ports, implement MBionomics.newMYname to evaluate their baseline values at time t, and MEffectSizes.newMYname to apply the intervention effects. These methods receive t, y, xds_obj, and s, and return the updated xds_obj.

The SI module is an example of a module using the shared parameter helpers for feeding rate (f), human fraction (q), mortality (g), emigration (sigma), emigration loss (mu), egg-batch rate (nu), and EIP duration. Use only the parameters relevant to the model.

Interface outputs

Implement the following methods with one value per patch:

  • F_fqZ.newMYname returns the daily density of infectious mosquito bites on humans (fqZ). The transmission interface uses it to compute EIR by human stratum.
  • F_fqM.newMYname returns the daily density of mosquito bites on humans (fqM). The transmission interface uses it to compute HBR by human stratum.
  • F_eggs.newMYname returns daily egg production by adult mosquitoes in each patch. The egg-laying interface distributes the eggs among habitats.

Each method receives t, y, xds_obj, and s.

#' @return a numeric vector with one value per patch
#' @export
F_fqZ.newMYname <- function(t, y, xds_obj, s) {

}

Skill set and checks

Optional methods and tests

Implement steady_state_M.newMYname, steady_state_Y.newMYname, or steady_state_MY.newMYname only when the corresponding steady state is defined for the model. The MY interface does not define MY-specific plotting generics; model-specific plots can use the parsed output from parse_MY_orbits.newMYname.

Add the module to the appropriate source file in ramp.library and write tests that check the equations and integration with ramp.xds. For example, check that initial values have the expected names and dimensions, that derivatives or updates preserve state ordering, and that the biting and egg outputs have one value per patch.

Reusable model code

ramp.xds has a modular design that allows published models to serve as dynamical components in new models for malaria and other mosquito-transmitted pathogens, including ordinary and delay differential equation models and stochastic or deterministic discrete-time models.

The mathematics supporting this framework are described in Spatial Dynamics of Malaria Transmission. 1
